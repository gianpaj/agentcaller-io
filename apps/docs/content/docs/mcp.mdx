AgentCaller has a remote MCP foundation at `/mcp`. It is disabled by default.
The available tool is `get_billing_status`, which reports billing as unavailable.
Card enrollment, call quoting, scheduling and monthly collection remain under
implementation. Existing API-key and operator routes retain their behavior.

## Configure an isolated deployment

Apply the Supabase migrations in timestamp order. Set `NEXT_PUBLIC_APP_URL` to
the exact application origin and configure the existing Supabase environment.
The canonical MCP resource is that origin plus `/mcp`.

Configure Supabase's OAuth server with authorization path `/oauth/consent`.
Use authorization code with PKCE and the target host's supported client registration.
The issuer owns registered redirects, code exchange and refresh tokens. See
[Supabase OAuth setup](https://supabase.com/docs/guides/auth/oauth-server/getting-started).

The platform requires asymmetrically signed ES256/RS256 access tokens with the
configured Supabase issuer, a verified human subject, OAuth `client_id`, expiry,
issue time and the exact MCP resource audience. Generic browser tokens and
tokens with only `aud: authenticated` are rejected. Prove the deployed issuer
can honor resource binding before claiming host compatibility. No host has a
completed end-to-end acceptance test in this implementation increment.

`MCP_ENABLED=true` enables discovery, consent and the transport in an isolated
environment. It does not enable billing or dialing. HTTP is allowed only on
loopback for development. Browser requests must use the configured application
origin or an exact origin in `MCP_ALLOWED_ORIGINS`; server clients may omit Origin.
Protected-resource metadata is at `/.well-known/oauth-protected-resource/mcp`.
The endpoint serves stateless current (2026-07-28) and legacy (2025) requests.

## Human connection flow

An eligible user can sign in through the configured GitHub provider and approve
tool access without a pre-created client profile or copied API key. Profile
ownership comes from the verified Supabase UID. Disabled profiles stay disabled;
an email or integration name cannot claim a legacy account.

Tool consent covers call and billing tools. Spending approval and saved-card
setup are separate requirements. OAuth approval cannot authorize a paid call.
The host can refresh credentials or reconnect without creating another connection.
Delegated OAuth tokens cannot authorize human portal settings or consent actions.

The human can disconnect an integration under **Settings → Manage connected
integrations**. Subsequent requests are denied even while a token remains valid.
Disconnecting also revokes the issuer grant and its refresh tokens. Refresh and repeated issuer consent cannot restore a revoked connection. Human
reauthorization of revoked connections remains unavailable in this increment.

## Verification

Offline tests cover signed-token validation, ownership, constrained login return,
consent denial/replay, discovery and both transport eras. `pnpm test:billing-db`
uses a fresh local PostgreSQL container to test concurrent first login and
consent, foreign-owner constraints, RLS and revocation. These tests do not prove
Supabase project configuration or compatibility with a particular MCP host.
