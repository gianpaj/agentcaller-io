AgentCaller publishes discovery resources from the platform at
`https://agentcaller.io`:

| Resource                                    | Purpose                                                                           |
| ------------------------------------------- | --------------------------------------------------------------------------------- |
| `/robots.txt`                               | Allows public crawling and excludes portal, authentication, and API paths         |
| `/sitemap.xml`                              | Lists canonical, indexable public pages on this host                              |
| `/.well-known/api-catalog`                  | Links the call API to its OpenAPI description, documentation, and health endpoint |
| `/openapi.json`                             | Describes the active call API                                                     |
| `/auth.md`                                  | Explains API-key provisioning and conditional human-approved OAuth access         |
| `/.well-known/oauth-protected-resource/mcp` | Advertises the MCP resource and configured OAuth issuer when MCP is enabled       |

The homepage returns `Link` headers with the `api-catalog`, `service-desc`,
`service-doc`, and `describedby` relations. The static discovery documents are
public and do not require a database connection or provider credentials. MCP
metadata requires an enabled, configured deployment; it returns HTTP 503 when
onboarding is disabled or unconfigured.

Discovery describes production only. The catalog, `auth.md`, robots and sitemap
use absolute `https://agentcaller.io` URLs, so an agent that starts from a
preview or self-hosted deployment is sent to production. Previews require
Vercel login and are not meant for agent discovery.

## Credentials

API-key access uses an enabled client profile and an operator-provisioned `ac_`
key in the `Authorization: Bearer` header. Portal login does not issue API keys.
There is no public API-key issuance endpoint.

[MCP onboarding](/mcp) uses the configured Supabase OAuth issuer and human
tool-access consent. It can provision the verified human's client profile without
an operator-created profile. `MCP_ENABLED` defaults to `false`; when enabled,
the resource metadata points to the issuer that owns client registration, code
exchange, and refresh tokens. Access tokens must target the exact MCP resource
audience. Generic browser tokens do not grant delegated API access.

Resource-bound OAuth supports MCP, billing endpoints, call quotes,
`stripe_postpaid` creation, and reading or cancelling the integration's own calls.
Call listing, deletion, transcripts, recordings, and legacy x402 or operator-funded
creation require API keys. API keys need an explicit integration link before
they can spend. Read `/auth.md` for the credential workflows and
[saved-card billing](/billing) for separate human spending and card approval.
Paid calling remains disabled pending release acceptance.
