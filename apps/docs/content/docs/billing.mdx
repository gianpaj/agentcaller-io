---
title: Saved-card billing
description: Enrollment, bounded reservations and monthly Stripe Invoicing
---

A human saves a card once; their agent then books calls against monthly limits,
and usage is invoiced through Stripe each month. **Paid calling is not yet
available.** There are no subscriptions or upfront payments.

## Enroll through your agent

1. Connect through [OAuth MCP onboarding](/mcp) and approve tool access.
2. Ask the agent to run `setup_billing` and open the returned AgentCaller link.
3. Sign in as the same human who connected the integration. Review approved USD
   tariffs, the name used to introduce your call, monthly and per-call limits,
   and the monthly collection agreement.
4. Approve spending and save a card in Stripe Checkout. The setup has no charge.
5. Let the agent poll readiness and submit its call. Opening a setup link or
   returning from Checkout cannot activate spending authority.

Setup links expire
in 24 hours; Checkout expires in 31 minutes. Links use a private continuation
cookie after initial exchange. Share them only with the account owner.

## Agent API

MCP exposes `setup_billing`, `get_billing_status`, `quote_call`, `schedule_call`,
`get_call_status` and `get_usage`. An API key must be explicitly linked to an
owned integration under **Billing** in the portal navigation before it can spend.
OAuth tokens require the resource-bound audience described in the MCP guide.

| Endpoint                         | Purpose                                               |
| -------------------------------- | ----------------------------------------------------- |
| `POST /api/v1/billing/setup`     | Create/reuse setup with an `Idempotency-Key`          |
| `GET /api/v1/billing/setup/{id}` | Poll own integration's setup                          |
| `GET /api/v1/billing/status`     | Read readiness and shared headroom                    |
| `GET /api/v1/billing/usage`      | Read integration-scoped usage; paginate with `before` |
| `POST /api/v1/calls/quote`       | Quote a validated `connect_me` job                    |
| `POST /api/v1/calls`             | Reserve with `X-AgentCaller-Funding: stripe_postpaid` |

Resource-bound OAuth can read or cancel its own integration’s calls through the
existing call detail/cancel routes. An OAuth cancel finalizes usage
immediately. OAuth tokens cannot delete calls or read transcripts. Legacy API
keys retain tenant-wide scope.

Card requests use integer `maxAmountCents`, the accepted `quoteVersion` and an
optional offset-resolved `scheduledFor`. Use a fresh quote before submitting;
quotes expire at the next five-minute UTC boundary. Never combine card funding
with `PAYMENT-SIGNATURE`. Existing omitted-header x402 and operator requests keep
their separate behavior and dollar inputs.

| Field              | Rule                                           |
| ------------------ | ---------------------------------------------- |
| `task.type`        | `connect_me` only; unknown fields are rejected |
| `maxAmountCents`   | Integer, 1–50,000                              |
| `task.maxAttempts` | 1–6; exactly 1 when `callingWindow` is `"now"` |
| Each leg           | At most 1,800 seconds                          |
| `scheduledFor`     | Optional; the job must fit within seven days   |

The business leg uses the destination country's rate. The callback leg always
uses the Spanish (`ES`) rate. Both must be approved USD rates for the current
pricing version, otherwise the request returns `503`.

The quote returns `maximumCents`, `quoteVersion`, `pricingVersion`,
`scheduledFor`, `periodStartsAt`, `periodEndsAt` and `expiresAt`. An accepted
call returns `201` with `{ "data": { id, state, paymentState, fundingSource,
usageState, reservedCents, finalCents, scheduledFor } }`.

| Status | Meaning                                                                                                                                                                         |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `403`  | No current spending authority                                                                                                                                                   |
| `409`  | `billing_setup_required`, a changed quote, a per-call ceiling, a closing billing period, the monthly allowance or the shared exposure limit, or a reused key with changed input |
| `422`  | Invalid input, a voice that is not enabled, or card funding combined with a `PAYMENT-SIGNATURE` or `X-Payment` header                                                           |
| `429`  | Call rate or outstanding-call limit reached                                                                                                                                     |
| `503`  | Paid calling is disabled, or approved tariffs are unavailable                                                                                                                   |

Usage lists return 50 rows per page with a `nextCursor`; pass it as `before`.

A request needing enrollment returns `409` with `billing_setup_required`, a setup
request ID and an AgentCaller URL. It creates no call or reservation. Retry the
same input/key after setup while the quote and schedule remain valid. For an
accepted call, exact replay returns its existing state even after expiry;
changed input with that key returns `409`.

## Allowances and usage

Accepting a call reserves the full worst-case job, including both connected legs
and all permitted attempts. The available amount is bounded by the account month, integration month,
per-call ceilings and **USD 10 shared unpaid usage plus reservations** across
all integrations and months. This is an exposure ceiling, not prepaid balance.

Usage is measured from telephony signals. Each dialed leg that rings incurs its
connection fee, even when nobody answers (busy, no answer, or a callback that is
not picked up). A connected leg also incurs its started minutes from the answer.
A business answer is billable even when the callback or handoff fails. The
combined call is rounded up to a cent once and never exceeds its reservation.
A job that ends without dialing releases its reservation at no charge.

A scheduled job belongs to its first-start UTC month. No new attempt starts after
that month ends. Active calls can finish within their existing bounds. The call
introduces you with the name the human approved at setup. A month is invoiced
once all its calls have final usage.

## Monthly collection and controls

Each month with usage produces one Stripe invoice, charged automatically to the
saved card. Months with no usage produce no invoice. Positive totals below the USD card minimum of
50 cents are waived with an audit record, without customer balance debt.

Stripe handles payment attempts, retries, reminders and card authentication.
Refunds, disputes and partial payments are reviewed manually. Paying an invoice
does not restore revoked spending.

**Billing** in the portal navigation shows card details, periods, invoices and grants.
Limit reductions cannot undercut committed usage or reservations. Revoking
spending cancels outstanding calls.
Withdrawing automatic collection blocks new calls, cancels open saved-card
calls and pauses Stripe automation on unpaid invoices. A payment already in flight can complete; incurred usage
remains due. Private hosted invoice URLs are available only to the verified human.

The billing page may also link to the Stripe customer portal for invoice history
and billing details. To replace the card, run billing setup again.
